01  The three-layer thesis

Logical scope, cryptographic scope, delegated identity

Each layer solves a different kind of isolation. Conflating them is the main risk this brief exists to rule out.

Do not conflate the three: a gbrain grant is not a decrypt key, and an ENS permission is not a decrypt key either
LAYER 1
gbrain = logical
Sources + per-MCP-client --federated-read / --bound-slug-prefixes grants. Application-level authorization, not a security boundary on its own.
LAYER 2
Cypher Brain = cryptographic
Snapshot → encrypt → Arweave today ships one ciphertext for the whole brain. Scoped snapshot is the missing piece.
LAYER 3
ENS = delegation
Agent wallet gets a narrow onchain permission (e.g. ROLE_SET_TEXT on one key), never the owner key. Not verified this session.

04  The path that actually closes the gap

No gbrain fork, no Cypher Brain rewrite required

The bulk-export gap (row 3 above) is closable with a thin wrapper, not core surgery — list --source-id + get --source-id already do the real work.

Only the middle step (tmp export dir assembly) is new code — the two left boxes were verified live this session; cypher-brain --dir on the right is existing, unmodified code, not re-exercised this session
