Cypher Brain × ENSv25

Our solution｜two wallets, one narrow permission

The owner uses their real wallet once, to grant a separate agent wallet permission for exactly one field.

🔑

Owner wallet

The real key. Used only once. Never saved to disk.

ens-setup
grants a permission for one field
🤖

Agent wallet

Generated by cypher-brain. Handles all daily updates by itself.

ens-verify: proving the permission is really narrow

Positive check — did the expected value actually get written? Negative check — does the same wallet really fail to write to a different field? Both together are what make this a proof, not a claim.

No custom smart contract was written -- this uses only what ENSv2 already provides

What this makes possible｜even a stolen agent key is contained

If the agent wallet is ever compromised, here is everything it can, and cannot, do.

Agent wallet(if stolen)
✓Update one text keythe single key it was granted
✕Move fundsno spending permission exists
✕Write other keysreverts on-chain, proven live
✕Act as the ownerowner's real key is never shared

Not just a claim

This boundary is verifiable by anyone -- ens-verify's on-chain proof is public, not our word for it.

This proves the integration is functionally central, not a cosmetic add-on
